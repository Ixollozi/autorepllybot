## 0. Одной фразой

Бот подключён к **рабочему TG-аккаунту через официальную Chat Automation / Secretary Mode** (без Telethon): читает входящие, отвечает **от имени аккаунта**, дублирует диалог владельцу в личку с ботом и под голосовыми кладёт **транскрибацию**. Ведёт клиента **до подтверждённого ТЗ без цены и без сроков сдачи**, пишет в **NSTLeadGen** с v1.

Человек: цена, договор, оффтоп/проверка «ты бот?», нестандарт.

## 1. Проблема и цель

### 1.1. Боль сейчас

| Симптом | Цена |
|--------|------|
| Клиент пишет в личку → ответ через часы/сутки | Холод, «уже нашли других» |
| Голосовые 30–90 сек не читаются с телефона в потоке | Пропуск смысла, потеря SLA |
| Discovery уезжает в «скиньте в TG» без структуры | Нет брифа → нет КП → нет сделки |
| Ответ руками = узкое место владельца | Не масштабируется |

Поле NST: интерес → «в Telegram» без детали. Главный рычаг — **скорость и качество первого касания**, не «ещё одна красивая фраза».

### 1.2. KPI продукта (не vanity)

1. **Time-to-first-reply** ≤ 60 сек в рабочее / ≤ 2 мин ночью (авто-режим).  
2. **% диалогов с заполненным брифом** (минимум 2 из 4 слотов).  
3. **% диалогов с подтверждённым резюме ТЗ** (клиент сказал «да / верно»).  
4. **% эскалаций вовремя** (бот не «варит» возражение «дорого» сам ценой).  
5. **Качество лида до человека** (человек тратит ≤10 мин на КП вместо 40 мин на допрос).

**Не KPI:** «звучит умно», число сообщений бота, длина промпта.

### 1.3. Что сознательно НЕ делает бот (v1)

- Не называет **цены**, вилки пакетов, скидки, предоплату.  
- Не обещает **сроки сдачи** («за 7 дней», «к пятнице сделаем»).  
- Не подписывает договор и не берёт оплату.  
- Не врёт кейсы/цифры.  
- Не спорит агрессивно.  
- Не отвечает за владельца в чатах, где включён **ручной режим / takeover**.

Срок запуска клиент *может назвать в брифе* как сигнал для человека — в **артефакт ТЗ для клиента срок сдачи не пишется**. Человек сам решает, как использовать дату в КП.

## 3. Архитектура (обязательная модель)

### 3.1. Почему только Bot API + Business Connection (без Telethon)

Telegram официально даёт **Secretary / Business / Chat Automation**: бот подключается к профилю в  
`Настройки → Business → Chatbots` (или «Автоматизация чатов»), получает `business_message`, отвечает через `business_connection_id` — **клиент видит сообщение от рабочего аккаунта**, не от `@bot`.

| Задача | Как |
|--------|-----|
| Ответ клиенту «как человек» | `sendMessage(..., business_connection_id=…)` |
| Inbox владельцу | Обычный DM бота → owner `chat_id` (копия текста + voice file + транскрипт) |
| STT | Скачать `file_id` из business_message → local Whisper |
| Продажи | LLM + state machine |
| CRM | HTTP API NSTLeadGen |

**Плюсы vs Telethon:** нет MTProto-session, ниже риск бана, проще ToS, один процесс.  
**Минусы / ограничения:** нужен аккаунт с Business-фичами (часто Premium); права `can_reply`; политика Telegram §5.4 для Business-ботов; ответы только в чатах, куда приходят updates по connection.

**Подключение (ops):**

1. @BotFather → Bot Settings → **Business Mode / Secretary Mode** → Enable.  
2. Рабочий аккаунт → Settings → Business → Chatbots → `@your_bot` → разрешить **Reply** (+ read).  
3. Бот ловит `business_connection` → сохраняет `business_connection_id`.  
4. Owner делает `/start` боту в личке → это inbox.

**Референс UX (скриншот) в inbox:**

```
{Имя} · Голосовое сообщение
🗣️ Расшифровка голосового:
«…текст…»
[🤖 Настройки] [🧑 Взять диалог]
```

### 3.2. Поток данных (happy path)

```
Клиент → DM рабочего аккаунта
        ↓
 Bot API update: business_message
        ├─► copy media/text → DM владельца (inbox)
        ├─► voice/video_note → STT (local) → расшифровка в inbox
        ├─► intent filter (работа / оффтоп / цена / takeover)
        ├─► LLM + state → reply через business_connection_id
        └─► sync → NSTLeadGen (msg1, notes, status, score)

Владелец пишет сам в тот же чат (message from business account, not bot):
        → детект «человек ответил» → TAKEOVER на чат
```

### 3.3. Стек (v1)

| Слой | Выбор | Почему |
|------|--------|--------|
| Runtime | Python 3.12+ | aiogram + faster-whisper |
| Telegram | **aiogram 3** + Business updates | без Telethon |
| БД | SQLite → Postgres | 1 оператор ок на SQLite |
| STT | **faster-whisper** `small`/`base` CPU | бесплатно, приватно |
| LLM | облако с жёстким system (выбор при старте кода) | локальная LLM для продаж слабее |
| CRM | NSTLeadGen REST (`/api/leads`, notes) | сразу |
| Деплой | VPS 24/7 + systemd/docker | Whisper на той же машине |
| Секреты | `.env` вне git | |

VPS: ≥2 vCPU / 2–4 GB RAM для Whisper `small` на CPU; иначе `base`/`tiny` + очередь.

### 3.4. Уровень ответа (глобальный)

Коротко: **AUTO / ASSIST / MANUAL** + per-chat **TAKEOVER**.  
Все остальные рычаги (ночь, маска, глубина воронки…) — в **§11 Настройки**, не путать с «режимом ответа».

## 5. M1 — Inbox и пересылка (как на скрине)

### 5.1. Что дублировать владельцу в inbox

Все `business_message` от клиентов **кроме**:

- чатов в `ignore_list`;  
- уже обработанных дублей (dedupe по `business_connection_id` + `message_id`);  
- служебного шума (по эвристике).  

Исходящие от владельца с телефона (если приходят как `business_message` edited/outgoing — по факту API): детект → **TAKEOVER**, в inbox пометка «вы ответили вручную».

### 5.2. Формат карточки в inbox (Bot → owner)

**Текст:**

```
👤 {name} (@username | id:{id})
📎 {type_label} · {time_local}
────────────────
{text or «(медиа без подписи)»}
```

**Голос / кружок / видеосообщение:**

1. Bot скачивает media по `file_id` из business_message → `sendVoice`/`sendVideoNote` владельцу в DM.  
2. Следом текст:

```
{Имя} · Голосовое сообщение
🗣️ Расшифровка голосового:
«{transcript}»

confidence: {ok|low}
lang: {ru|uz|mixed}
```

Inline: `[🤖 Настройки]` `[⏸ Пауза на чат]` `[🧑 Взять диалог]`

### 5.3. Исходящие от владельца

Если владелец сам ответил клиенту с рабочего аккаунта — бот ставит **TAKEOVER** (дефолт 120 мин или до кнопки «Бот снова»). Иначе перебьёт человека.

### 5.4. Группы

v1: **только личные DM**. Группы — out of scope (отдельное ТЗ).

## 6. M2 — Транскрибация

### 6.1. Типы

| Тип Telegram | Обработка |
|--------------|-----------|
| `voice` | да |
| `video_note` (кружок) | да (аудиодорожка) |
| `audio` / `document` audio | да, если audio/* |
| `video` с речью | фаза 2 |
| Текст | STT не нужен |

### 6.2. Пайплайн (local faster-whisper)

1. Скачать media через Bot API `getFile`.  
2. ffmpeg → 16 kHz mono wav.  
3. `faster-whisper` модель `small` (fallback `base` на слабом VPS); `language=ru`, auto-detect если уверенность низкая; UZ — отдельный проход/флаг.  
4. Постобработка: пунктуация; мат **не** вычищать по умолчанию (смысл важнее); опция `clean_profanity`.  
5. Сохранить `transcripts` + inbox.  
6. Sales-brain: **вход = transcript**.

**Почему не облако:** критерий «бесплатно» → $0 за минуту. VPS и так нужен боту. Облако (Groq free tier / OpenAI) — только fallback при падении локали.

### 6.3. SLA и ошибки

- Цель: ≤ 30 сек на ≤ 2 мин аудио (CPU `small`).  
- Fail: «Не удалось расшифровать — оригинал выше» + алерт.  
- > 10 мин → отказ/обрезка с пометкой.

### 6.4. Приватность

Транскрипты = персональные данные диалога. Хранить N дней (дефолт 90), не логировать в публичные каналы, `.env` ключи не в git.

## 7. M3 — Sales brain: принципы ответов

### 7.1. Персона

- Язык: **«вы»**, коротко, по делу, как в скрипте NST.  
- Один оффер / один следующий шаг за сообщение.  
- Не анкета из 8 пунктов.  
- Не «как ИИ-ассистент», не канцелярит.  
- RU по умолчанию; если клиент на UZ — отвечать на UZ (шаблоны Combo + LLM).  
- Портфолио: **ровно 2 кейса + вилка**, не пять ссылок.

### 7.2. Источник правды

Жёстко в system/RAG:

1. Скрипт продаж NST (Msg1-Combo, вилки, бриф, возражения — *без блока цены*).  
2. Карточка услуг NST (что делаем / что нет) — без прайса.  
3. Библиотека кейсов (только approved факты).  
4. FAQ / границы (не бесплатный полный макет до предоплаты и т.д.).

Любая цена/срок сдачи в ответе модели = **баг**. Фильтр-гард на выходе (regex + LLM judge).

### 7.3. Стиль длины

- Msg1-Combo: 1 сообщение, читается за 20–40 сек.  
- Бриф: 1 вопрос = 1 сообщение.  
- Между ответами: короткая человеческая реакция («понял», «отлично, это упрощает»).  
- Не слать два сообщения подряд без нужды (исключение: кейс + текст).  
- Ночью — **тот же** стиль и воронка (полный AUTO), без «ответим утром».

### 7.4. Маска + только работа (анти-спаление / оффтоп)

**Позиция:** клиенту не раскрываем «я бот» в каждом сообщении. Но бот **не** ведёт себя как друг/личный ассистент.

**Разрешённые темы:** услуги NST, ниша клиента, бриф, кейсы, процесс работы, эскалация к менеджеру, уточнения по проекту.

**Запрещённые / оффтоп (детектор + hard refuse):**

- «Напиши стих / код / домашнее / перевод не по делу»  
- Политика, отношения, медицина не по проекту, «поболтаем»  
- «Докажи что ты живой»: фото, голос «скажи пароль», созвон «прямо сейчас без менеджера» как тест  
- Личные данные владельца не по работе  
- Любые темы вне digital-услуг NST

**Ответ при оффтопе (шаблон, коротко):**

```
Я по рабочим вопросам по сайтам/ботам/заявкам —
давайте вернёмся к вашей задаче: [последний открытый слот брифа / вилка].
Если нужен живой менеджер — напишите «менеджер», подключу.
```

**Если прямо «ты бот / ИИ?»:**

```
Тут переписку по проектам ведём быстро текстом; по цене и договору
подключается менеджер. Можем продолжить по задаче — или зовите менеджера.
```

Не врать «я Самир лично сижу 3 ночи». Не оправдываться эссе. Сразу развилка: работа / менеджер.  
Параллельно — **эскалация в inbox** с тегом `caught_or_offtopic`.

### 7.5. Output guards (обязательные)

Перед отправкой клиенту:

1. Нет цен (`$`, `сум`, `у.е.`, «от N», «пакет за»).  
2. Нет обещаний срока сдачи («за 7 дней сделаем», «к пятнице готово»).  
3. Нет оффтоп-контента (классификатор).  
4. Только whitelist кейсов.  
5. Язык «вы», длина в лимите.

## 8. M4 — State machine воронки

### 8.1. Состояния диалога

```
NEW
  → GREETING_QUALIFY          # кто вы / что нужно (мягко)
  → MSG1_COMBO_SENT           # 2 кейса + вилка
  → WAIT_FORK                 # ждём «1»/«2»/свой вариант
  → BRIEF_Q1 … BRIEF_Q3       # мини-бриф (см. 8.3)
  → TZ_DRAFT_SENT             # резюме ТЗ без цены/сроков сдачи
  → WAIT_TZ_CONFIRM           # «всё верно?»
  → TZ_CONFIRMED              # → эскалация человеку + стоп продаж-бота
  → OBJECTION_HANDLING        # подсостояние
  → NURTURE                   # дожим / тишина
  → DISQUALIFIED              # вежливый выход
  → HUMAN_TAKEOVER
  → CLOSED
```

Переходы логируются: `from → to`, `trigger`, `ts`.

### 8.2. Входные сценарии

| Вход | Поведение |
|------|-----------|
| Холодный «здравствуйте» / «интересен сайт» | GREETING → быстро к Combo или 1 уточнение ниши |
| Уже после звонка («вы звонили») | Combo с нишевым шаблоном, без допроса «кто вы» |
| «Прайс / сколько стоит» рано | Не цена. «Чтобы назвать точно — 2–3 вопроса / сначала формат» → вилка или бриф |
| «Только посмотреть» | Лёгкий Combo; не тяжёлый разбор; скор C |
| Очевидный no-budget / «бесплатно сделайте всё» | DISQUALIFIED или границы по скрипту → эскалация |
| Узбекский | Combo UZ + вилка |
| Голос | STT → тот же state, что и текст |

### 8.3. Мини-бриф (адаптация скрипта 10a под бота)

Бот собирает слоты (один вопрос за раз, с вилкой):

| Слот | Вопрос (смысл) | В артефакт ТЗ |
|------|----------------|---------------|
| **FORK** | Формат из вилки (лендинг / сайт+заявка / бот / …) | да |
| **Q1** | Главное действие посетителя (запись / заявка / звонок / TG) | да |
| **Q2** | Что уже есть (лого, фото, тексты, IG/2GIS/сайт) | да |
| **Q3** | Объём разделов | да |
| **Q4 timing** | «К какой дате хотели бы запуститься?» — **да, спрашиваем** | В **CRM note / inbox** как `client_timing_signal`. В текст резюме ТЗ клиенту — **не** включать |

**Зачем Q4, если ТЗ «без сроков»:**  
В скрипте срок нужен человеку для КП и FOMO. Бот **не обещает** «сдадим к дате». Он только узнаёт желания клиента и отдаёт менеджеру. Клиент в финале видит scope без даты сдачи и без цены — менеджер сам решит, как использовать сигнал.

### 8.4. Финал — резюме ТЗ (клиенту)

Шаблон:

```
Итого, ваш проект выглядит так:

— формат: {fork}
— главное действие: {q1}
— материалы: используем {q2}; с нашей стороны — {scope_from_policy}
— разделы: {q3}

Без оценки стоимости и сроков на этом шаге —
сначала фиксируем задачу, затем менеджер пришлёт варианты решения.

Всё верно, ничего не забыли?
```

После «да» → состояние `TZ_CONFIRMED`:

1. Бот клиенту: «Отлично, зафиксировал. Сейчас подключится менеджер с вариантами — обычно в течение {SLA_human}.»  
2. Inbox владельцу: карточка лида + JSON/Markdown ТЗ + ссылка на чат + скоринг.  
3. Автоответы продаж **стоп** (только FAQ «когда ответ?» / soft nurture).

### 8.5. Тишина (nurture)

| Пауза | Действие |
|-------|----------|
| 4–12 ч после вилки | Переспрос вилки (не «ну как?») |
| 24 ч в брифе | Продолжение работы: «набросал структуру под {q1}, остался 1 вопрос…» |
| 3+ дня | 1 мягкий дожим → NURTURE sleep / CLOSED |

Не спамить >1 follow-up в сутки.

### 8.6. Возражения (бот)

Обрабатывает **по скрипту**, но:

| Возражение | Бот | Человек |
|------------|-----|---------|
| «Нет времени / в TG» | Уже здесь — Combo | — |
| «Дорого» без цифры от нас | Перевод в ценность/формат, **без цены** → эскалация | Даёт вилку цен |
| «Пришлите прайс агентства» | «Прайс без задачи врёт; 2 вопроса → ТЗ → точный расчёт» | — |
| «Бесплатный полный макет» | Граница скрипта | при давлении — HUMAN |
| Юр. / договор / гарантии | Коротко + HUMAN | всегда |
| Конкурент назвал цену | Не торговаться цифрой → HUMAN | |

Минимум для `TZ_DRAFT_SENT`: FORK + Q1 + (Q2 или Q3). Q4 желателен, но не блокер резюме.

## 9a. M9 — Синк с NSTLeadGen (v1, обязательно)

**Prod CRM:** `https://crm.neosamptech.uz`  
**Уже есть в CRM:** `LANDING_API_KEY` + `POST /api/leads/inbound` (лендинг → создание лида по `X-API-Key`).  
**Чего нет:** lookup по telegram, patch `msg1_*`, notes, idempotent events для автоответчика.

### 9a.0. Варианты авторизации (разбор) → выбранный

| # | Вариант | Плюсы | Минусы | Вердикт |
|---|---------|-------|--------|---------|
| A | Бот логинится как user (`POST /api/auth/login`) → JWT | Ноль правок CRM | Пароль в `.env` бота; JWT ~7 дней; rate-limit login; бот = «человек» в actor_id; хрупко | ❌ не v1 |
| B | Расширить inbound тем же `LANDING_API_KEY` (create-only) | Уже на проде | Не умеет update/notes/msg1 — только создание | ❌ мало |
| C | **Integration API + `X-API-Key`** (тот же ключ или `AUTOREPLY_API_KEY`) | Как лендинг; без JWT; узкие эндпоинты; идемпотентность | Нужен небольшой патч CRM на проде | ✅ **делаем** |
| D | Отдельный роль `bot` + JWT без expiry | Аудит actor | Сложнее security.py; всё равно JWT | позже |
| E | Бот пишет прямо в SQLite CRM | «Быстро» | Ломает изоляцию, бэкапы, concurrent | ❌ запрещено |
| F | CRM → webhook в бота | Удобно для «менеджер взял чат» | Не закрывает push msg1/brief из бота | доп. позже |

**Что буду делать (C):**

1. В NSTLeadGen добавить тонкий роутер `/api/integrations/autoreply/...` (или `/api/leads/autoreply/...`) с проверкой `X-API-Key`  
   - предпочтительно **отдельный** `AUTOREPLY_API_KEY` (если пуст — fallback на `LANDING_API_KEY`, чтобы не блокировать старт).  
2. Эндпоинты:
   - `GET .../lookup?telegram=@x|id` — найти лида  
   - `POST .../upsert` — создать/обновить минимум полей (`source=tg_autoreply`, status `Написал` при новом)  
   - `PATCH .../{id}` — `msg1_sent`, `msg1_reply`, `msg2_*`, `script_score`, `script_branch`, `qualification_json`, status  
   - `POST .../{id}/notes` — текст брифа/эскалации  
   - `POST .../{id}/events` — идемпотентные события (`Idempotency-Key` / `external_event_id`)  
3. Автоответчик на VPS: `CRM_BASE_URL=https://crm.neosamptech.uz` + ключ в `.env`.  
4. Лендинговый `inbound` **не трогаем** по контракту (чтобы сайт не сломать).

### 9a.1. Матчинг лида

1. По `telegram` (@username или numeric id).  
2. Fallback: телефон, если клиент скинул.  
3. Нет матча → upsert (`source=tg_autoreply`, `status=Написал`) + note «входящий TG».

### 9a.2. Что писать в CRM

| Событие бота | Поле / действие NSTLeadGen |
|--------------|----------------------------|
| Ушёл Msg1-Combo | `msg1_sent=true` |
| Ответ на вилку / Msg1 | `msg1_reply=true` |
| Примеры отдельно (если были) | `msg2_sent` / `msg2_replied` по факту |
| Скор эвристикой | `script_score` A–D |
| Ветка | `script_branch` при наличии |
| Слот брифа / резюме ТЗ | `LeadNote` markdown + JSON в `qualification_json` |

| Эскалация / оффтоп | note + optional touch |

### 9a.3. Идемпотентность

Ключ `external_event_id` = `tg:{chat_id}:{message_id}:{event_type}` — повтор не плодит notes.

### 9a.4. LLM-ключи: единый сейф в CRM (решение)

**Идея:** один раз завёл ключи в Настройках CRM → и КП в CRM, и автоответчик живут с одного пула. В `.env` бота только `CRM_BASE_URL` + `AUTOREPLY_API_KEY` (+ bot token). Без дубля Groq/Gemini.

#### Как устроено сейчас в CRM
- Таблица `groq_api_keys` + UI `GroqKeysPanel` + env `GROQ_API_KEYS`
- In-memory `GroqKeyPool` с ротацией на 429
- Админ CRUD: `/api/system/groq-keys`

#### Что добавим в CRM

| Часть | Действие |
|-------|----------|
| Модель `gemini_api_keys` | Зеркало `groq_api_keys` (label, key, hash, suffix, is_active) |
| UI | Вторая панель «Gemini» рядом с Groq (тот же UX: bulk add, on/off, reload) |
| Env optional | `GEMINI_API_KEYS` / `GEMINI_API_KEY` — как у Groq |
| Пул | `GeminiKeyPool` (та же логика 429 → rotate) |
| Integration | `GET /api/integrations/llm-keys` под `X-API-Key` |

**Ответ `GET .../llm-keys` (только для AUTOREPLY_API_KEY):**

```json
{
  "groq": {
    "model": "llama-3.3-70b-versatile",
    "keys": ["gsk_…", "gsk_…"]
  },
  "gemini": {
    "model": "gemini-2.0-flash",
    "keys": ["AIza…"]
  },
  "refreshed_at": "ISO8601",
  "ttl_sec": 300
}
```

В UI админу ключи по-прежнему маскируются (`***xxxx`); наружу полные значения — **только** integration endpoint с service key.

#### Поведение автоответчика

1. Старт / каждые `ttl_sec` (и при 401/пустом пуле) — `GET llm-keys`.  
2. Локальная ротация: Groq first → на исчерпании/ошибках → Gemini.  
3. При 429 — next key в том же провайдере, потом failover.  
4. Если оба пула пусты → шаблонный ack + алерт «AI keys empty» в inbox.  
5. Ключи **не логировать**; в логах только suffix.

#### Альтернативы (не выбранные для v1)

| Вариант | Суть | Почему не сейчас |
|---------|------|------------------|
| CRM как LLM-proxy | Бот шлёт prompt, CRM дергает Groq/Gemini | Ключи не уходят из CRM — безопаснее, но latency + CRM SPOF + объём доработки |
| Ключи только в `.env` бота | Дубль пулов | Расходится с CRM, «не чётко» |
| Бот логинится JWT и читает `/system/groq-keys` | Admin API | Сейчас API **не отдаёт** полный `api_key` в list (правильно) |

**v2 (опционально):** `POST /api/integrations/llm/chat` — proxy, если захотим ключи вообще не отдавать боту.

### 9a.5. Объём патча CRM под ключи + лиды

Один деплой CRM:

1. Integration router (`AUTOREPLY_API_KEY` / fallback `LANDING_API_KEY`)  
2. Lead upsert/patch/notes/events (§9a.0)  
3. Gemini pool + Settings UI  
4. `GET .../llm-keys`  
5. Тесты на auth, маскирование в admin API, выдачу полных ключей только integration-ключу  

Автоответчик: клиент `crm.py` → `refresh_llm_keys()` + `crm_leads.*`.

## 11. M7 — Настройки и режимы (управление поведением)

Настройки живут в БД бота (hot-reload), правятся из **личного чата с ботом** (кнопка «Настройки» / `/settings`).  
Per-chat оверрайды сильнее глобальных на время действия.

### 11.0. Два слоя (не смешивать)

| Слой | Что | Пример |
|------|-----|--------|
| **A. Режим ответа** | Имеет ли бот право писать клиенту | AUTO / ASSIST / MANUAL / TAKEOVER |
| **B. Политики поведения** | *Как* пишет, когда, о чём, насколько агрессивно | ночь, маска, глубина воронки, follow-up |

---

### 11.1. Режим ответа (глобально)

| Код | Поведение | Когда включать |
|-----|-----------|----------------|
| `AUTO` | Сам читает → думает → отвечает клиенту | Обычная работа (дефолт) |
| `ASSIST` | Черновик только вам в inbox; клиенту — после «✅ Отправить» | Когда учите тон / боитесь ляпа |
| `MANUAL` | Только inbox + STT, ответов нет | Отпуск, кризис, ручной день |
| `TAKEOVER` | Не глобальный: **на чат**. Человек ведёт; бот молчит, STT/лог живут | После вашего ответа с телефона или кнопки |

Кнопки быстрого доступа в каждом алерте inbox: `[⏸ Пауза чат]` `[🧑 Взять]` `[🤖 Бот снова]`.

---

### 11.2. Политики — что выносим в настройки

#### 1) Идентичность (маска)

| Режим | Клиенту | Риск |
|-------|---------|------|
| `mask` *(дефолт по решению)* | Как менеджер NST, без «я ИИ» | Спалят → §7.4 |
| `disclose` | В первом/редком сообщении: «ассистент NST, по цене подключится менеджер» | Честнее, чуть ниже «человечность» |
| `disclose_on_ask` | Маска, пока не спросят «ты бот?» → честный ответ | Компромисс |

#### 2) Ночной режим (`night_policy`)

Рабочие часы: `Asia/Tashkent`, напр. 09:00–21:00 (редактируемо).

| Режим | Ночью |
|-------|--------|
| `full_auto` *(дефолт)* | Полная воронка как днём |
| `ack_only` | «Получили, разберём с утра с {time}» + inbox вам; без брифа/Combo ночью |
| `silent` | Тишина клиенту, только inbox+STT вам |
| `assist_night` | Ночью как ASSIST (черновики вам) |

День всегда следует глобальному `AUTO/ASSIST/MANUAL`, если не оверрайд.

#### 3) Глубина продаж (`sales_depth`)

| Режим | До куда бот доводит |
|-------|---------------------|
| `ack` | Только «на связи / приняли» |
| `combo` | До Msg1-Combo + вилка, дальше человек |
| `brief` | До мини-брифа, без резюме ТЗ |
| `full_tz` *(дефолт)* | До подтверждённого ТЗ без цены/сроков сдачи |

#### 4) Агрессивность follow-up (`nurture`)

| Режим | Тишина |
|-------|--------|
| `off` | Не дожимает |
| `soft` *(дефолт)* | 1 переспрос вилки 4–12ч + 1 дожим в брифе |
| `active` | До 1 follow-up/сутки, цепочка до 3 дней |

Жёсткий потолок: никогда >1 исходящего follow-up в сутки на чат.

#### 5) Эскалация (`escalation`)

| Режим | Когда зовёт человека |
|-------|----------------------|
| `paranoid` | Любая цена, любой «бот?», любой нестандарт, low confidence |
| `normal` *(дефолт)* | Цена / ТЗ confirm / токсик / оффтоп-повтор / юр. |
| `late` | Только явная просьба менеджера + ТЗ confirm + токсик |

#### 6) Язык (`language`)

| Режим | Поведение |
|-------|-----------|
| `auto` *(дефолт)* | Детект ru/uz по сообщению |
| `ru` / `uz` | Форс |
| `mirror` | Отвечать на языке последнего сообщения клиента |

#### 7) Транскрибация (`stt`)

- вкл / выкл  
- типы: voice / video_note / audio (чекбоксы)  
- `clean_profanity` on/off  
- слать расшифровку **только вам** (всегда) vs ещё и … *(клиенту не шлём в v1)*

#### 8) Inbox (`inbox`)

- дублировать все сообщения / только голос+медиа / только если бот ответил  
- превью длины текста  
- кнопки под каждым: настройки / пауза / takeover  
- тихие часы для *ваших* пушей (не путать с night_policy клиенту)

#### 9) Человечность ответа (`tempo`)

| Режим | Задержка перед ответом |
|-------|------------------------|
| `instant` | ~0.5–1 с (риск «робот») |
| `human` *(дефолт)* | 1.5–4 с + typing |
| `slow` | 5–12 с (имитация занятости) |

+ `typing_indicator` on/off.

#### 10) Оффтоп / границы (`scope`)

| Режим | |
|-------|--|
| `work_only` *(дефолт)* | Только услуги NST; оффтоп → отказ §7.4 |
| `work_plus_smalltalk` | 1 короткий smalltalk, потом к делу |
| `strict` | Любой не-бриф → сразу «менеджер?» |

#### 11) CRM sync (`crm`)

- sync on/off  
- автосоздание лида если нет матча  
- какие события писать (msg1 / notes / tz / все)

#### 12) Ниши Combo (`niches`)

Вкл/выкл шаблонов: стоматология / ритейл / учебка / generic.  
Дефолтная ниша, если не определили.

#### 13) Лимиты безопасности (`limits`)

- макс. исходящих бота на чат / час  
- макс. длина ответа (символы)  
- стоп-слова → сразу HUMAN (редактируемый список)  
- ignore list user_id / @username

#### 14) Per-chat оверрайды

На карточке чата в inbox:

- пауза N минут / до ручного снятия  
- форс `sales_depth` для этого лида  
- форс язык  
- «не синкать в CRM»  
- закреплённый скор A–D

### Inbox / STT / Business

- [ ] Входящее на рабочий аккаунт → `business_message` → inbox ≤5 сек.  
- [ ] Ответ через `business_connection_id` виден клиенту от аккаунта, не от бота.  
- [ ] Голос: медиа владельцу + расшифровка как на референсе.  
- [ ] Кружок расшифровывается локально.  
- [ ] Владелец ответил вручную → takeover.  
- [ ] `can_reply=false` → алерт, бот не падает молча.

### Продажи

- [ ] Combo без цены; бриф по одному вопросу.  
- [ ] Q4 пишется в CRM/note, не в клиентское резюме ТЗ.  
- [ ] После «да» — стоп + алерт + CRM.  
- [ ] «Сколько стоит?» — без цифр.  
- [ ] Оффтоп / «напиши стих» — отказ по шаблону + алерт.  
- [ ] Guard ловит цену и срок сдачи.

### CRM

- [ ] msg1_sent / msg1_reply выставляются.  
- [ ] Brief note появляется в лиде.  
- [ ] Нет лида → создаётся `source=tg_autoreply`.  
- [ ] Повтор события не плодит дубли notes.

### Ops

- [ ] `/mode` работает.  
- [ ] Рестарт восстанавливает state + `business_connection_id`.  
- [ ] Секреты не в git.
